## 一、从实际场景确定 IT 资产管理系统的范围

为了让后续的数据模型、资产生命周期和工作流设计更加具体，本文以一家约有 300 名员工的科技公司为例。

这家公司在多个办公地点运营，同时有部分员工远程办公。IT 团队需要统一管理电脑、显示器、手机、外设和网络设备，但相关信息目前分散在 Excel、共享表格和员工聊天记录中。

日常资产管理主要涉及以下场景：

- 新员工入职时，查找并分配可用设备；
- 员工离职时，核对并回收其名下资产；
- 设备在员工、部门或办公地点之间调拨；
- 设备发生故障时，记录送修过程和处理结果；
- 查询设备的当前位置、使用人、状态和保修期限；
- 追溯设备过去的领用、归还、调拨和维修记录。

## 二、设计 IT 资产管理系统的核心结构

业务范围明确后，接下来需要进一步梳理系统要保存哪些数据、不同数据之间如何关联，以及资产状态和业务流程如何设计。这部分也可以先让 AI 协助完成：根据前面整理的业务场景，AI 可以识别核心数据对象、拆分数据关系，并初步设计资产状态和业务流程，再由业务人员结合实际规则进行确认和调整。

下面就以本文的员工设备管理场景为例，具体看看 IT 资产管理系统的核心结构应该如何设计。

### 1. 建立以资产台账为核心的数据结构

一套基础的员工设备管理系统，主要包含三种数据类型：

其中，资产台账是整个系统的核心，每一条记录对应一项可以被单独管理的具体资产。资产编号和序列号应设置唯一性规则，避免同一设备被重复录入。

对于需要被多项资产重复引用和统一维护的信息，例如**资产分类、设备型号、员工、部门和办公地点**，可以建立独立数据表并与资产台账关联。数据量较少、管理要求较简单时，品牌、型号和供应商等信息也可以先作为资产字段保存，再根据后续需要调整数据结构。

![数据结构-emwtds.png](https://static-docs.nocobase.com/%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84-emwtds.png)

系统中的主要数据关系以具体资产为中心，包含多组关系型数据模型中常见的**一对多关系**：一个资产分类或设备型号可以对应多项具体资产，一名员工可以持有多项资产，一项资产也可以关联多条分配、归还、调拨和维修记录。员工、部门、办公地点等基础资料通过关联字段重复引用，供应商则可以根据需要与维修记录关联，既能减少重复录入，也方便后续查询和统计。

![it数据关系 cn-xynm2u.png](https://static-docs.nocobase.com/it%E6%95%B0%E6%8D%AE%E5%85%B3%E7%B3%BB%20cn-xynm2u.png)

其中，资产台账保存设备当前的使用人、部门、办公地点、状态及采购与保修信息；业务记录保存资产过去发生的分配、归还、调拨和维修。每次业务操作都应在更新资产台账的同时新增对应记录，保证当前信息与历史变化保持一致。

### 2. 定义资产状态与流转规则

资产台账中需要设置“当前状态”字段，用于表示设备目前是否可用，以及正处于哪个管理阶段。资产从登记、使用到最终退役的过程，可以通过当前状态和历史业务记录共同反映。

在梳理状态规则时，也可以把登记、分配、归还、维修和退役等场景交给 AI，让它先整理出可能的状态、转换路径，以及需要同步更新的数据。

基础系统可以先设置四种资产状态：

状态之间的变化由具体业务操作触发：

```Plain
资产登记完成 → 可用

可用
  └─ 分配 → 使用中

使用中
  ├─ 归还并检查通过 → 可用
  ├─ 送修或归还后发现故障 → 维修中
  └─ 确认不再继续使用 → 已退役

维修中
  ├─ 维修完成 → 可用
  └─ 无法修复 → 已退役
```

这里的“可用”“使用中”“维修中”和“已退役”是资产状态；“分配”“归还”“调拨”“送修”和“维修完成”则是业务动作。业务动作可以改变资产状态，也可能只改变使用人、部门或办公地点。

例如，归还设备后，系统需要根据检查结果决定下一状态：设备正常则恢复为可用，发现故障则进入维修中，确认无法继续使用时进入已退役。因此，业务动作与状态变化并不是固定的一一对应关系。

对于需要检查、审批或等待处理的场景，还可以增加已预留、待检查、待调拨和待报废等中间状态。只有当资产确实需要在某个环节停留时，才有必要增加对应状态。

### 3. 将高频业务操作配置为工作流

前面已经确定了资产台账中的当前信息、业务记录和状态转换规则。工作流的作用，是将这些规则组合成一次完整操作，避免管理员分别修改资产状态、当前使用人、办公地点和历史记录。

无论是分配、归还还是维修，一次完整的业务操作通常都包含以下几个环节：

```Plain
校验当前数据和操作权限 → 更新资产台账 → 新增对应的业务记录 → 发送通知或触发后续处理
```

调拨是否需要单独建立工作流，可以根据实际使用频率决定。如果企业需要清楚记录资产从哪个员工、部门或地点转到哪里，建议保留独立的调拨记录；如果只偶尔调整办公地点，也可以在其他操作中更新位置并保留变更记录。

![工作流1-5bgrn1.png](https://static-docs.nocobase.com/%E5%B7%A5%E4%BD%9C%E6%B5%811-5bgrn1.png)

工作流需要保证相关数据同步更新。以资产分配为例，只有当前使用人、资产状态和分配记录都更新成功，这次操作才算完成；如果某个环节出现问题，系统应撤回本次修改，避免留下前后不一致的数据。

以设备维修为例，工作流触发后，系统会将资产状态更新为“维修中”，同时生成维修记录，用于跟踪维修供应商、维修类型、处理状态、费用和完成时间。维修完成后，再根据处理结果将资产恢复为“可用”或转为“已退役”。

### 4. 用管理看板汇总资产状态

随着资产台账和业务记录逐渐积累，团队可以通过管理看板了解整体资产情况，并快速找到需要处理的设备。

看板数据可以直接从资产台账和各类业务记录中汇总。例如，资产数量和状态分布来自资产台账，维修趋势来自维修记录，即将过保的设备则根据保修日期筛选。

资产状态、分类分布和变化趋势适合使用图表展示；需要继续处理的事项则更适合使用明细列表，例如即将过保、正在维修、超过预计归还日期、长期未分配或维修次数较多的设备。

## 三、使用 AI Agent 和 NocoBase 搭建系统

前面已经完成了数据模型、资产状态和转换规则、业务工作流及管理看板的设计。接下来，可以使用 AI Agent 连接 NocoBase，将这些设计转换为数据表、关联关系、页面、业务操作和工作流。

### 1. 明确 AI Agent、NocoBase 和业务人员的分工

在系统搭建过程中，三者承担的任务不同。

业务人员负责说明实际需求，并确认资产状态、操作条件、角色权限和异常处理规则。例如，设备归还后是否需要检查、部门负责人可以查看哪些资产，以及维修中的设备是否允许重新分配，都需要结合企业制度确定。

AI Agent 负责将这些业务规则整理成可执行的系统配置。连接 NocoBase 后，它可以创建数据表和关联关系，搭建列表、表单和详情页，配置工作流和权限，也可以在后续需求变化时继续调整已有结构。**NocoBase 官方提供 CLI 和 [Skills](https://github.com/nocobase/skills)，Claude Code、Codex、Cursor、OpenCode 等 AI Agent 能够参与数据建模、页面搭建、工作流编排和权限配置。**

> 💡 如何将 AI Agent 接入 NocoBase？阅读官方指南：[https://docs.nocobase.com/cn/ai-builder](https://docs.nocobase.com/cn/ai-builder)

例如，设备分配后，当前使用人、部门、办公地点、资产状态和分配记录是否同步更新；设备归还或维修完成后，资产是否按照前面定义的转换规则进入正确状态。确认数据关系、工作流和权限都符合实际要求后，再导入正式数据。

### 3. 接入现有数据并完成上线检查

正式接入前，需要按照已定义的基础资料、资产台账和业务记录统一字段名称、关联关系与状态值，并清理重复或无效数据。少量数据验证通过后，再导入或连接完整资产数据。

如果现有资产信息保存在 Excel 或共享表格中，可以统一字段和数据格式后批量导入；如果数据已经存储在企业数据库或其他业务系统中，也可以通过 NocoBase 的数据源或 API 接入，减少重复录入。

同时，还需要根据实际职责配置权限，明确不同角色可以进入哪些页面、执行哪些操作，以及查看和修改哪些数据。在 NocoBase 中，还可以进一步设置字段级权限。例如，普通员工只能查看自己使用的资产，部门负责人可以查看本部门资产，IT 管理员负责分配、归还、维修和退役；资产状态、当前使用人等关键字段，则只允许指定角色查看或修改。

### 4. 将 AI 融入日常资产管理

系统上线后，AI 还可以继续参与日常资产管理。

AI Agent 主要用于调整字段、页面和工作流，AI 员工则基于 NocoBase 中的结构化数据，在授权范围内完成信息录入、查询、汇总和报告生成。对于资产分配、状态变更、设备退役和责任确认等会修改正式数据的操作，仍需通过系统权限和工作流执行。

#### 自动提取资产信息

IT 管理员收到采购清单、发票、资产标签照片或设备交接说明后，可以让 AI 员工识别设备类型、品牌型号、资产编号、序列号、采购日期和保修期限，并将结果自动填写到资产表单中。

对于资产编号、序列号和保修日期等关键字段，仍需由管理员确认，并结合唯一性规则检查是否存在重复或识别错误。

在搭建 ITAM、ITSM 等需要长期运行的企业业务系统时，我们仍然建议选择像 NocoBase 这样兼顾业务底座与 AI 能力的平台：既能提供稳定的数据模型、权限体系和工作流能力，也能借助 AI Agent 加快系统搭建，并通过 AI 员工参与后续运营。这样，系统不仅能够快速完成原型，更能真正落地到业务中，长期运行，并随着管理需求持续扩展。
